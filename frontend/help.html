Scheduling logic

Dependencies and offsets tell the system when work can actually begin

If Task 2 must wait for Task 1 and then start after 3 more days, add the dependency and offset there itself. Saralta then shifts the live bar and shows the delayed baseline in Gantt, so schedule slippage is visible instead of hidden.

Quick start

How to begin using the software

If you are new, follow this sequence first. It mirrors the way Saralta is designed to be used in practice.

01

Open your workspace

Use the Workspace page to manage structure, members, activities, tasks, and operational records in one place.

02

Set the hierarchy

Create divisions, then groups, then activities or projects, and finally teams so every task lives under the correct chain.

03

Create tasks properly

Define due date or ongoing schedule, assign responsibility, and use dependency plus offset fields when a task must wait.

04

Track using views

Use Dashboard for action handling, Gantt for schedule movement, and Statistics for high-level reporting and trend review.

One interesting example: from task creation to delay visibility

This example is the easiest way to understand how Saralta thinks about schedule logic.

A

Create Task 1

Suppose Task 1 is a prerequisite work item and ends on 10 April.

B

Create Task 2

Set Task 2 to depend on Task 1 finishing, but also add an offset of 3 days.

C

What the system does

Task 2 will not start immediately on 10 April. It will shift to 13 April automatically because of the offset.

D

What you will see

The Gantt chart shows the original baseline as delayed and the active bar at the actual shifted schedule with visible delay count.

Role guide

What each user type should focus on

Admin / heads

Set structure and control flow

Define hierarchy, approve where needed, assign teams, monitor overall activity, and use statistics and Gantt to detect bottlenecks early.

Project directors / leads

Drive execution planning

Create actionable tasks, distribute responsibility, break work into subtasks, attach dependencies, and keep schedules realistic.

Members

Update and close work cleanly

Work from assigned tasks, keep status updated, collaborate through chat and comments, and submit completion proof instead of closing informally.

Best practice

Use the system in a way that keeps plans trustworthy

Plan dependencies with offsets only when the waiting gap is real

If Task 2 should begin after Task 1 plus a mandatory waiting period, use dependency offset so the schedule and Gantt view remain honest.

Prefer subtasks for internal execution detail

Keep the main task readable and push smaller execution units into subtasks so accountability and review stay manageable.

Use proof-based completion instead of informal closure

That preserves evidence, approval trace, and history so audits and follow-up reviews are much easier later.

Check Gantt and Statistics regularly, not only when something slips

Those views help identify early schedule pressure, recurring delays, and load imbalance before problems become visible in execution.
